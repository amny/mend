# 既知の制約と将来の候補（MVP）

## 既知の制約

### 中身を全部消した要素がクリックできなくなる

要素内のテキストを全部消すと、テキストノードは空のまま残り `<br>` も入らない（AC-06）。そのため要素の高さが 0 になり、クリックしてカーソルを置けなくなることがある。

- MVP では、Undo（Ctrl+Z）か変更箇所一覧の「この変更を戻す」で元に戻せれば許容とする。
- 保存後に再び入力する場合も、まず Undo で戻してから編集する。
- 確認手順：`docs/manual-tests.md` の MT-03。

### 壊れたHTMLでテキストを全部消すと、保存できないことがある

閉じタグの入れ子が崩れた箇所では、ブラウザ（と parse5）が書式要素を複製して補う。そのテキストを全部消すと複製が作られなくなり、構造が変わるため、保存前の検証で保存が中止される。

- 例：`fixtures/malformed.html` の `<p><b><i>入れ子違反</b>の続き</i>の文</p>` で「の続き」を全部消す（`<i>` の複製が消える）
- 文字を1文字でも残せば保存できる。Undo か「この変更を戻す」で戻してから保存する。

### 段落の末尾に入れた `<br>`

段落の末尾で Shift+Enter を押しても、何か入力するまで新しい行は見た目に現れない（カーソルは新しい行にある）。末尾の `<br>` は次の文字がないと行を作らないため。

- 何も入力しないまま保存すると、ファイルには末尾の `<br>` だけが書かれ、ブラウザでも空の行は表示されない。
- 編集画面では、空の行に DOM だけのゼロ幅スペースを置いてカーソルを置けるようにしている（保存はされない）。

### 保存した `<br>` は Undo で消せない

保存すると、入れた `<br>` はファイルの一部になる。保存より前に入れた `<br>`（と、その行の文字の修正）は、保存後に Undo で消せない。その段落の Undo 履歴は保存の時点で消える。ほかの箇所の文字の修正は、これまでどおり保存をまたいで Undo できる。

- 保存した `<br>` は、元のファイルにあった `<br>` と同じ扱いになり、Mend では消せない。消すかもしれない改行は、保存する前に Undo か行頭の BackSpace で取り消す。

### 編集できないテキスト

次のテキストは編集の対象外（表示はされる）。

- `<head>` 内、`<script>` `<style>` `<template>` `<textarea>` の中身、空白のみのテキストノード
- `<svg>` `<math>` の中、`<option>`、`<button>` の中
- 位置対応表から復元した文字列が parse5 の値と一致しないテキストノード（例：`<table>` 直下のテキスト。表の中のマークアップをまたいで1つのノードに結合されるため）
- 解析結果と iframe の DOM が食い違う文書は、全体を読み取り専用で開く

### ファイルの扱い（Web版）

- ドラッグ＆ドロップでファイルハンドルが得られなかった場合、上書き保存の先がわからないため、保存すると保存先を尋ねる（別名保存と同じ動作）。
- 最近開いたファイルにはフォルダのパスを表示しない（ブラウザから取得できないため）。開き直すときに改めて権限を求める。

### プレビュー

- `sandbox="allow-scripts"` のみで表示するため、`alert()` などのダイアログは表示されない。
- 外部CSS・画像など相対パスの参照は解決されない（要件 6.2）。
