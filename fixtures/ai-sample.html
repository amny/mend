Mend 機能一覧

AIが出力したHTMLを、独自形式に変換せずそのまま編集するエディタ。ソースコードから機能と仕組みを整理したもの。

概要 構成 機能一覧 ファイル操作 表示 テキスト編集 保存処理 安全装置 キーボード操作 編集できない範囲・制約 パッケージ別 API

概要

Mend は「開く、文字を直す、保存する」で完結する HTML エディタ。元の HTML 文字列だけを正本とし、変更したテキストだけをソースに書き戻すことで、編集していない部分を1バイトも変えずに保存する。

元の文字列が正本

画面上の DOM を書き出さない。保存は { start, end, text } のパッチを元ソースに当てて作る。

編集していない所は不変

実体参照・改行コード・BOM・空白などの表記は、変更範囲の中でも元のまま残す。

検証に通らなければ書かない

新ソースを再パースして元の木と突き合わせ、一致しなければ保存を中止する。迷ったら編集不可の側に倒す。

スクリプトは実行しない

編集ビューは sandbox="allow-same-origin" の iframe。元の HTML に属性やタグを足さない。

画面

構成

packages/core

DOM に依存しない純粋なロジック（Vitest）。

  • UTF-8 の厳密なデコード、BOM の記録と復元
  • parse5 による解析とテキストレコード生成
  • テキスト位置 ↔ ソース位置の対応表
  • 差分（Myers）からパッチ生成・適用
  • 保存前検証、保存後の正本の再構築

packages/editor

iframe 上の編集（Playwright で E2E）。副作用はここに閉じ込める。

  • blob URL による iframe 表示
  • 構造ガード（事前防止＋事後巻き戻し）、IME
  • 自前の Undo / Redo 履歴
  • 変更一覧、検索、強調表示、ホバー枠
  • 保存後の再同期、意図しない遷移からの復帰
  • スクリプト有効のプレビュー

apps/web

React の画面と File System Access API。

  • 起動画面・編集画面・ダイアログ・トースト
  • FileAdapter（開く・上書き・別名保存・外部更新の検知）
  • 最近開いたファイル（IndexedDB）
  • 日本語の UI 文言、テスト用フック

保存の流れ

1. 変更の収集変更済みテキストノードの現在値（行）を集める editor.prepareSave
2. パッチ生成差分から置換範囲を求め、元の表記を残して符号化 encodeLines
3. パッチ適用重なりを確認して後ろから適用 applyPatches
4. 保存前検証再パースして元の木と突き合わせ verifySave
5. 書き込み外部更新を確認してから書き込み FileAdapter.save
6. 再同期新ソースを正本にし対応表だけ張り直す editor.commitSave

2〜4 のどこかで失敗すると、ファイルには書き込まずに理由をダイアログで示す。

ファイル操作

F-01

開く

apps/web/src/lib/fileAdapter.ts · App.tsx · StartScreen.tsx
  • 起動画面の「ファイルを開く」（Ctrl+O）で showOpenFilePicker を開く。対象は .html / .htm。
  • 起動画面のドロップ先、または編集画面全体へのドラッグ＆ドロップで開ける。ファイルハンドルが取れればそれを使い、取れなければ File だけで開く（このときは保存先が決まらないので、保存は常に別名保存になる）。フォルダのドロップはエラー。
  • UTF-8 を fatal でデコードし、不正なバイト列があれば開かない。Shift_JIS など別の文字コードの可能性をダイアログで伝える。
  • BOM の有無を記録し、保存時に同じ状態で書き戻す。
  • 読み取り権限がなければ確認を出し、拒否されたら理由を表示する。
F-02

上書き保存

fileAdapter.ts · EditorScreen.tsx
  • 「保存」ボタンまたは Ctrl+S（iframe にフォーカスがあっても有効）。
  • 書き込み権限を確認し、createWritable で一時ファイルに書いてから置き換える。途中で失敗したらストリームを破棄し、元ファイルは変えない。
  • 成功するとトーストで「変更 N箇所。それ以外の部分は元のファイルと一致しています。」を表示。変更がなければ元と同じ内容で保存したと示す。
  • 保存中は保存ボタンを無効にし、二重実行を防ぐ。
F-03

別名で保存

fileAdapter.ts
  • 「別名で保存」ボタンまたは Ctrl+Shift+S。showSaveFilePicker で元ファイルと同じ場所・同じ名前を初期値にする。
  • 保存後は新しいファイルが以降の上書き先になり、ヘッダーのファイル名も切り替わる。キャンセル時は何もしない。
F-04

未保存警告

App.tsx
  • 未保存の変更があると、ウィンドウタイトルに「● ファイル名 - Mend」、ヘッダーに「未保存の変更 N件」を表示。
  • 別ファイルを開く・ドロップする・ロゴで起動画面に戻るときは「保存されていない変更があります」で確認（キャンセル／変更を破棄して続ける）。
  • タブを閉じる・再読み込みするときはブラウザ標準の beforeunload 確認を出す。
F-05

外部更新の検知

fileAdapter.ts modifiedOnDisk · EditorScreen.tsx
  • 上書き保存の直前に、ディスク上の lastModified を開いた時点（または前回保存時点）と比べる。
  • 変わっていれば「ファイルが別の場所で更新されています」を出し、キャンセル／別名で保存／上書きするを選ばせる。検証済みのソースはそのまま使う。
F-06

最近開いたファイル

apps/web/src/lib/recentFiles.ts · format.ts
  • ファイルハンドルを IndexedDB（DB mend、ストア recent-files）に保存。isSameEntry で重複をまとめ、最大10件。
  • 起動画面に名前と最後に開いた日（「今日」「昨日」「11月12日」、別の年は年付き）を新しい順に表示。フォルダのパスはブラウザから取れないため出さない。
  • 開き直すときは改めて読み取り権限を求める。

表示

V-01

編集ビュー

packages/editor/src/editor.ts
  • 元のソースを blob URL にして、sandbox="allow-same-origin"（allow-scripts なし）の iframe に読み込み、designMode で編集可能にする。スクリプトは実行されず、CSS は元のまま効く。
  • srcdoc ではなく blob URL を使うのは、doctype のない文書で parse5 とブラウザの描画モードを一致させるため。
  • 読み込み後、iframe の DOM と parse5 の木を並行に走査し、テキストノードとレコードの対応表を作る（mapping.ts）。一致しなければ文書全体を読み取り専用にする。
V-02

プレビュー

packages/editor/src/preview.ts
  • ヘッダーの「編集／プレビュー」で切り替える。プレビューは sandbox="allow-scripts" のみ（同一オリジンなし）の iframe で、スクリプトが動く読み取り専用表示。
  • 表示するのは「今の変更を当てて検証まで通したソース」。ファイルには書かない。検証に通らない場合はプレビューを作らず理由を表示する。
  • ステータスバーは「編集モード：スクリプト無効」「プレビュー：スクリプト有効」を切り替えて表示。
V-03

編集可能範囲の明示（ホバー枠）

packages/editor/src/overlay.ts
  • 編集できるテキストの上にマウスを乗せると、その要素に薄い枠と要素名（例：p.lead）のラベルを出す。上に余白がなければラベルを枠の内側に置く。
  • 枠は親ページ側に重ねた層で描き、iframe の DOM にはノードを足さない。script / style など編集対象外には反応しない。スクロールすると消える。
V-04

変更箇所・検索結果の強調

editor.ts（Highlight API）
  • 未保存の変更で実際に変わった文字の範囲を黄色、検索一致を薄い緑、現在の一致を濃い緑で強調する。
  • CSS Custom Highlight API を使い、スタイルは iframe の adoptedStyleSheets で与える。DOM にノードも属性も足さない。

テキスト編集

E-01

文字の挿入・削除（IME 対応）

editor.ts
  • 既存のテキストノードの中で、入力・BackSpace・Delete・選択範囲の置き換えができる。
  • 選択範囲の置き換えやテキストを空にする削除は、Chrome にノードを消させないよう自前で data を書き換える（空にしても要素は残り、<br> は入らない）。
  • IME の変換中（compositionstart〜compositionend）は構造チェックを保留し、確定後にまとめて判定して1つの Undo 単位にする。
  • カーソル位置は「見出し › 要素」の形でステータスバーに表示する。
E-02

構造変更のブロック

editor.ts（beforeinput / MutationObserver）· revert.ts

「事前に止める」と「事後に巻き戻す」の二段構え。

  • 事前防止：beforeinput で insertParagraph（Enter）・リスト／水平線／リンクの挿入・format*（装飾）・ドロップ・ドラッグ削除などを止める。Ctrl+B / I / U も無効。
  • 削除は getTargetRanges() を見て、範囲が複数のノードにまたがる場合は止める。
  • 事後の巻き戻し：MutationObserver で、対応表にあるテキストの変更だけを受け入れる。要素の増減や属性の変更は記録を逆順に逆適用して元に戻す。戻せなかった場合は編集を止める（保存は可能）。
  • 改行が表示される要素（white-space: pre / pre-wrap / pre-line / break-spaces）の中では、Enter と Shift+Enter で改行文字を入れる。
E-03

貼り付け

editor.ts · textRange.ts flattenLineBreaks
  • クリップボードの text/plain だけを使い、装飾は捨てる。
  • 改行はスペースに置き換える（要素を増やさない）。改行が表示される要素の中では改行のまま入れる。
  • 貼り付けは1回で1つの Undo 単位になる。
E-04

Undo / Redo

packages/editor/src/history.ts
  • ブラウザ標準の Undo は使わず、Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z と historyUndo / historyRedo を横取りして自前の履歴を使う。ヘッダーにもボタンがある。
  • 履歴はソース上の位置ではなく「テキストノードと変更前・変更後の値」で持つ純粋なデータ。種類は入力・IME・貼り付け・取り消し・<br> の挿入削除・グループ。
  • 同じノードへの連続入力は 500ms 以内ならまとめる。Undo/Redo の直後はまとめない。
  • 保存しても履歴は消えず、保存をまたいで戻せる（保存済みの <br> の挿入・削除は除く）。
  • Undo 後はカーソルを変わった位置に置く。すべて Undo して保存すると元とバイト一致する。
E-05

検索

SearchBar.tsx · textRange.ts findMatches
  • Ctrl+F または検索ボタンで検索バーを開く（プレビュー中なら編集ビューに切り替わる）。
  • ASCII の大文字小文字を区別せず、テキストノードをまたぐ一致も見つける。head / script / style / template / textarea / title の中は対象外。
  • 「現在 / 総数」の件数を表示。Enter で次、Shift+Enter で前、Esc で閉じる。一致箇所へスクロールする。
  • 編集でテキストが動いたら検索し直す。置換は未対応（将来）。
E-06

変更箇所一覧と個別の取り消し

ChangeList.tsx · editor.ts revealChange / revertChange
  • 左のサイドパネルに、未保存の変更をテキストノード単位で文書順に表示する。場所（例：「1. 背景と目的 › .card › p」）、変更前（取り消し線）、変更後。
  • 見えない文字を可視化する：U+00A0 は「⍽」、改行は「↵」、空は「（空）」。
  • 項目をクリックすると該当箇所へスクロールし、カーソルを変更位置に置く。
  • 「この変更を戻す」でその箇所だけ保存済みの値に戻す。取り消し自体も Undo 履歴に積む（<br> を含む場合はグループで1手）。
  • パネル下部に「保存時に、変更した文字以外が元のファイルと1文字も違わないことを確認します。」と表示。
E-07

<br> による改行

editor.ts insertBreak / joinLines · encodeEdit.ts encodeLines
  • 改行が表示されない要素で Shift+Enter を押すと、カーソル位置でテキストを分けて <br> を入れる。分けた各テキストは同じレコードの「行」として扱う。
  • 消せるのは自分で入れた未保存の <br> だけ。行頭の BackSpace・行末の Delete で前後の行をつなぐ。元のファイルにある <br> は消せない。
  • 書き方はファイル内の既存の書き方（<br/>、<br />、<BR>）に合わせ、なければ <br>。
  • 空の行には DOM 上だけゼロ幅スペースを置いてカーソルを置けるようにする（保存・変更一覧・履歴には含めない）。
  • 保存すると <br> はファイルの一部になり、以降は Undo で消せない。

保存処理

S-01

パッチ生成

packages/core/src/encodeEdit.ts · diff.ts · decodeText.ts
  • 解析時に、各テキストノードのソースを HTML トークナイザと同じ規則で読み直し、DOM 上の位置（UTF-16）→ソース上の位置の対応表（セグメント）を作る。文字参照と CR/CRLF は分割できない単位として扱う。
  • 元の値と現在の値の共通接頭辞・接尾辞を除いて変更範囲を求め、文字参照とサロゲートペアの区切りに合わせる。その中で Myers 差分を取り、変わっていない文字は元の表記（&nbsp; など）を残す。
  • 新しく入力した文字は & と < だけエスケープする。
  • Chrome が入れる U+00A0 は、新しい文字に限り単独なら通常スペースに戻し、連続スペースのときだけ &nbsp; にする（pre 系の中ではそのまま）。
  • 新しい改行は、そのテキスト内・直前・直後にあるソースの改行コード（CRLF / LF / CR）で書く。どこにもなければ LF。
  • 前後とつながって別の文字参照やタグに化ける場合（例：&not の後に in;）は、先頭1文字を数値文字参照で書く。pre 等の先頭で消される改行も参照で書く。
  • 安全に書き戻せない場合は例外にして保存を止める。
S-02

パッチ適用

packages/core/src/patch.ts
  • パッチ { start, end, text } の範囲外・重なり（同じ位置への2つの挿入を含む）を検出したら例外。
  • 後ろから順に適用し、前のオフセットを保つ。mapOffset で旧ソースの位置を新ソースへ写す。
S-03

保存前検証

packages/core/src/verify.ts · SaveErrorDialog
  • 新ソースを同じ設定（sourceCodeLocationInfo: true, scriptingEnabled: false）で再パースし、元の木と並行に比べる。
  • 比べるもの：パッチ範囲外のソース文字列、描画モード（quirks 等）、子の数、ノード種別、タグ名、属性（名前・値・順序・名前空間）、テキスト、コメント、doctype、<template> の中身。
  • 変更したテキストは書き戻し規則を当てた期待値と比べる。新しい <br> は期待値側に入れて比べる。空にしたテキストノードは再解析した木になくてよい。
  • 不一致は最大20件まで CSS 風のパス（例：section:nth-of-type(2) › table › tbody）付きで返す。
  • 失敗すると「保存を中止しました」ダイアログで理由と最初の不一致を示し、「該当箇所を表示」でその要素へスクロールできる。ファイルは書き換えない。
S-04

保存後フック

fileAdapter.ts AfterSaveHook · main.tsx
  • 書き込みに成功するたびに afterSave(oldSource, newSource, { name }) を呼ぶ。将来の Git 履歴用で、MVP では空の実装。
S-05

保存後の再同期

save.ts（rebase）· editor.ts commitSave · mapping.ts
  • iframe は読み込み直さない。保存したソースを新しい正本として解析し直し、今の DOM と並行走査して対応表だけを張り直す。
  • 中身を全部消したテキストノードは DOM にだけ残るので「仮想レコード」として残し、同じ ID・順序を保つ。<br> で分けたテキストは行ごとのノードに展開する。
  • Undo 履歴・スクロール位置・カーソル位置は保持する。保存中に入力された値も失わないよう、構造だけを比べる。
  • 張り直しに失敗した場合は、ファイルは保存済みのまま編集を止め、開き直すよう案内する。

安全装置

読み取り専用への切り替え

editor.ts ReadOnlyReason · messages.ts

次の場合は編集を止め、編集ビューの上にバナーで理由を表示する。ステータスバーは「読み取り専用」になり、変更一覧の「この変更を戻す」も隠れる。

理由コード状況保存

navigatediframe が別ページへの移動を繰り返した、または読み込み直せなかった未保存の変更は可

editor.ts · mapping.ts restoreVirtualTexts · history.ts mapNodes

編集できない範囲・制約

編集できないテキスト

解析時に各テキストノードへ状態（TextRecordStatus）を付け、editable 以外は編集を受け付けない。

状態対象
excluded-contexthead, script, style, template, textarea, title, xmp, iframe, noembed, noframes, plaintext, select, option, optgroup, button の中、および SVG・MathML など HTML 以外の名前空間
whitespaceASCII の空白だけのテキストノード
mapping-mismatchソースから復元した文字列が parse5 の値と一致しないもの（例：<table> 直下のテキスト、NUL を含むもの）。件数はステータスバーに表示

既知の制約

詳細と確認手順は docs/known-limitations.md と docs/manual-tests.md を参照。
  • 中身を全部消した要素はクリックできなくなる。Undo か「この変更を戻す」で戻す。
  • 壊れた HTML（入れ子違反など）でテキストを全部消すと、検証に通らず保存できないことがある。1文字でも残せば保存できる。
  • 段落末尾に入れた <br> の後に何も入力しないと、ブラウザ上では空行として表示されない。
  • 保存した <br> は元からある <br> と同じ扱いになり、Undo でも消せない。
  • ドロップでファイルハンドルが得られないと、保存は常に別名保存になる。
  • プレビューでは alert() などのダイアログは出ず、外部 CSS・画像などの相対パスは解決されない。
  • SVG 内のテキストの編集、置換、空要素へのクリック用の枠は将来の候補。
